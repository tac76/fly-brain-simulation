# Viewer Implementation Plan (Plan 2 of 3)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (chosen: native). Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A static web app that replays recordings in 3D: the physically simulated fly on a tabletop, the looming threat with its shadow, the whole brain as a glowing point cloud, synced charts, and a gallery page — buildable for GitHub Pages.

**Architecture:** Two Python scripts export shared assets once (fly meshes as GLB, neuron positions as a binary point file). A Vite + TypeScript + three.js app loads a gallery manifest, fetches a recording folder (format: `docs/recording-format.md`), and renders it with one WebGL renderer and two viewports (world, brain). No backend.

**Tech Stack:** Python: trimesh, fast-simplification (dev group `assets`). Web: Node ≥ 22, Vite, TypeScript (strict), three.js, uPlot, Vitest, ESLint, Playwright (Chromium).

**Spec:** `docs/superpowers/specs/2026-10-14-fly-brain-simulation-design.md` (§5, §6)

## Global Constraints

- Viewer lives in `viewer/`; no runtime dependency on Python or a server. `npm run build` output (`viewer/dist/`) is deployable as static files under a sub-path (`base: "./"`).
- Coordinates: all world objects sit inside one `THREE.Group` rotated −90° about X, so MuJoCo coordinates (mm, z up) are used unchanged inside it. Quaternions from `body.bin` are `(w, x, y, z)` → `new Quaternion(x, y, z, w)`.
- Brain points: FlyWire `pos_x/y/z` from `neuron_annotations.tsv`, voxel size (4, 4, 40) nm → µm, centred on the mean, y and z negated (FlyWire y points ventral). Point index = connectome neuron index (row of `Completeness_783.csv`); neurons without annotation get the mean position and group `unknown`.
- Asset size budget: `fly.glb` ≤ 4 MB, `brain_points.bin` ≤ 2.5 MB, one 3 s recording ≤ 3 MB.
- Frame playback at 50 fps × speed (0.1–2×); poses interpolated between frames (lerp position, slerp rotation).
- Spike glow: per-neuron `heat` set to 1 on a spike and decaying with half-life 60 ms of simulated time.
- The "How it works" overlay text names the hand-built parts exactly as the README does (stimulus encoding, motor mapping, gait controller, default walking).
- Derived data (`brain_points.bin`, gallery recordings) are CC BY-NC 4.0; the viewer footer says so and links FlyWire.
- Fonts/colours: dark theme, one accent colour for spikes (`#ffb347`), highlighted neuron groups in distinct colours with a legend.

## Review Focus

1. Recording with `status: aborted` or 0–1 frames → viewer shows the partial replay and an "aborted: <reason>" badge, no crash → test in Task 3 (reader) and Task 7 (e2e on an aborted fixture).
2. Recording whose `part_names` don't match the GLB nodes → clear error message listing missing parts → test in Task 4.
3. Brain-run recording vs no-brain recording (no `spikes`, no `threat_*` signals) → brain panel shows "no brain in this run", charts show drives only → tests in Tasks 5–6.
4. Window resize / mobile width → canvas and charts resize; layout stacks vertically below 900 px → checked in Task 7 screenshots.
5. Missing asset or 404 on a recording → visible error state instead of a blank page → test in Task 7.

### Task 1: Fly mesh export

**Files:** Create `scripts/export_meshes.py`, `tests/test_export_meshes.py`; Modify `pyproject.toml` (dependency group `assets = ["trimesh", "fast-simplification"]`)

**Interfaces:**
- Produces: `viewer/public/assets/fly.glb`: one node per mesh geom, node name = geom name (same order and names as `FlyBody.part_names`), vertices in geom frame (taken from the compiled MuJoCo model: `model.mesh_vert` / `mesh_face` via `geom_dataid`), units mm; per-part decimation to ≤ 30 % faces (min 200 faces per part) with `fast_simplification`; material colours: body amber-brown, eyes dark red, wings translucent grey.
- `def export_fly_glb(out: Path, target_ratio: float = 0.3) -> dict` returns `{"parts": n, "faces": total}`.

- [ ] Steps 2–4: RED → implement → GREEN. Step 5: run for real, commit the GLB and `feat: export fly meshes to glTF`.

**Interfaces:**

### Task 4: World scene

**Interfaces:**
